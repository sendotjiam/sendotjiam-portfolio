## 2. Numbered Findings List

### Group 1: Hard Gate / Critical (Priority: HIGH)

#### [Finding 01] R-03 · Mobile Touch Targets in Navigation Bars
- **Rule:** R-03 (Mobile Responsiveness), UI-UX-Pro-Max Priority 2, Hallmark Floor 1
- **File:** `src/components/Navbar.tsx:137,159`, `src/components/zest/ZestNav.tsx:46,124,139`
- **Issue:** Navigation icon buttons (`toggleTheme`, `setMobileMenuOpen`) are sized at `w-10 h-10` (40×40px) in `Navbar.tsx` and `w-8 h-8` (32×32px) in `ZestNav.tsx`. The back link on `ZestNav.tsx` measures 32×24px. All fail the mandatory 44×44px mobile touch target rule.
- **Proposed Fix:** Upgrade buttons to `min-w-[44px] min-h-[44px]` (or `w-11 h-11`) with centered SVG icons and 8px touch spacing.

#### [Finding 02] R-03 · Mobile Touch Targets in 3D Macropad Controls
- **Rule:** R-03 (Mobile Responsiveness), UI-UX-Pro-Max Priority 2
- **File:** `src/components/Macropad3D.tsx:1592-1645`
- **Issue:** The hardware button toolbar below the 3D canvas uses `h-8` (32px height) for switch profiles and `w-8 h-8` (32×32px) for sound and theme toggles, causing frequent tap errors on mobile devices.
- **Proposed Fix:** Pad the toolbar controls to a minimum 44px hit region (`h-11 px-4`, icon buttons `w-11 h-11`).

#### [Finding 03] R-03 · Mobile Touch Targets Across Content Sections
- **Rule:** R-03 (Mobile Responsiveness), UI-UX-Pro-Max Priority 2
- **File:** `src/components/Experience.tsx:94`, `src/components/Projects.tsx:132,148,173,183`, `src/components/Footer.tsx:26-64`
- **Issue:** Experience "App Store" links measure 75×25px; Project view mode switchers measure 26px height; carousel arrow buttons measure 32×32px; footer links measure 20px height without vertical hit padding.
- **Proposed Fix:** Apply minimum 44px hit bounds using invisible pseudo-elements (`after:inset-[-8px]`) or explicit padding.

#### [Finding 04] R-03 · Mobile Touch Targets in Zest Simulator & Cheatsheet
- **Rule:** R-03 (Mobile Responsiveness), UI-UX-Pro-Max Priority 2
- **File:** `src/components/zest/ZestSimulator.tsx:710,720,800+`, `src/components/zest/ZestArchitecture.tsx:103`, `src/components/zest/ZestShortcuts.tsx:68`, `src/components/zest/ZestDownload.tsx:86`
- **Issue:** Simulator HUD action buttons (pin, preview, transform, delete) are 20×20px (`w-5 h-5`); simulator reset is 33px height; architecture tabs are 36px height; shortcut filter tabs are 30px height; copy command button is 17px height.
- **Proposed Fix:** Re-pad all interactive buttons to meet 44px touch targets on mobile touch viewports.

#### [Finding 05] R-03 · Zest Floating HUD Mobile Positioning & Overflow Defect
- **Rule:** R-03 (Mobile Responsiveness), UI-UX-Pro-Max Priority 5
- **File:** `src/components/zest/ZestSimulator.tsx:780`
- **Issue:** The floating HUD container uses `<div className="absolute inset-x-3 top-5 sm:inset-x-auto sm:left-1/2 sm:-translate-x-1/2 w-full sm:w-[390px] ...">`. Combining `inset-x-3` (left: 12px) with `w-full` (width: 100%) pushes the right edge 12px beyond its parent container, overflowing by 12px on mobile screens (`overflowRight: 12px`).
- **Proposed Fix:** Replace `inset-x-3 w-full` with `left-3 right-3 w-auto sm:inset-x-auto sm:w-[390px]`.

#### [Finding 06] R-25 · Color Contrast Deficiencies on Micro-Type & Status Badges
- **Rule:** R-25 (Color Contrast WCAG AA), UI-UX-Pro-Max Priority 1, Hallmark Gate 75
- **File:** `src/components/Hero.tsx:201-203`, `src/components/Experience.tsx:74,149`, `src/components/zest/ZestSimulator.tsx:853+`
- **Issue:** Pillar numerals `01`–`05` in `text-[var(--teal)]` (`#0d9488`) on white card background have a contrast ratio of only **3.74:1** (fails WCAG AA 4.5:1 requirement for small text). In dark mode, `+5` overflow badge in `text-apple-tertiary` (`#6b7280`) on `#12141a` card measures **3.81:1**. Neutral text in simulator HUD (`text-neutral-400`, `text-neutral-500`) falls between **2.8:1** and **3.4:1**.
- **Proposed Fix:** Darken light mode teal to `#0f766e` (contrast 4.7:1); adjust dark mode tertiary label to `#9ca3af` (contrast >4.6:1).

#### [Finding 07] R-16 · AI Marketing Buzzword in Experience Data
- **Rule:** R-16 (Copywriting & Buzzwords)
- **File:** `src/data/experiences.ts:50`
- **Issue:** Contains banned AI marketing buzzword: `"creating a **seamless onboarding experience** that simplified user activation."`
- **Proposed Fix:** Replace with factual engineering outcome: `"streamlined the onboarding and registration architecture, eliminating UI jank and reducing new-driver activation drop-offs."`

#### [Finding 08] Hallmark Floor 1 · 37 Color Literal Violations Outside Design Tokens
- **Rule:** Hallmark Floor 1 (Gate 48)
- **File:** `src/app/globals.css:44-87,154-186`
- **Issue:** Sloplint reported 37 FAIL violations for raw RGBA and HEX colors (`rgba(26, 26, 31, 0.96)`, `#f4f3ef`, `#0a0b0e`, `#13151b`, `#12141a`, `rgba(0, 0, 0, 0.02)`, etc.) outside `:root` tokens.
- **Proposed Fix:** Declare all background, surface, and border values inside `:root` and `.dark` as semantic CSS custom properties in OKLCH, referencing only `var(--...)` in component selectors.

#### [Finding 09] Hallmark Floor 15 · CSS Stamp Case Sensitivity
- **Rule:** Hallmark Floor 15 (Gate 20)
- **File:** `src/app/globals.css:1`
- **Issue:** Line 1 uses lowercase `/* hallmark:2.0.0 ... */` instead of required PascalCase `/* Hallmark · ... */`, causing sloplint Gate 20 Floor FAIL.
- **Proposed Fix:** Update line 1 to standard Hallmark stamp syntax: `/* Hallmark · v2.0.0 · shape:split-hero-workbench · theme:japanese-artisan-sumi-shuiro · genre:playful */`.

#### [Finding 10] Hallmark Floor 5 · Display Heading Break-Word Hygiene
- **Rule:** Hallmark Floor 5 (Gate 50)
- **File:** `src/components/Hero.tsx:76`, `src/components/zest/ZestHero.tsx:46`
- **Issue:** `<h1>` headlines lack `break-words` (`overflow-wrap: break-word`) and `min-w-0`, risking clipping on narrow mobile viewports (e.g. 320px).
- **Proposed Fix:** Add `break-words min-w-0` to all display headlines.

#### [Finding 11] Hallmark Floor 7 · Script-Disabled SSR Resilience for Hero Macropad
- **Rule:** Hallmark Floor 7 (Gate 62)
- **File:** `src/components/Hero.tsx:7-17`
- **Issue:** With JavaScript disabled, `Macropad3D` displays an infinite pulsing loading spinner with no static navigation fallback links.
- **Proposed Fix:** Render a static HTML `<nav>` keyboard grid in the SSR skeleton so non-JS and search crawler visitors have direct navigation anchor links.

#### [Finding 12] Hallmark Floor 11 · Card Inside a Card & Simulated Window Chrome
- **Rule:** Hallmark Floor 11 (Gate 4 & Gate 47a)
- **File:** `src/components/zest/ZestHero.tsx:111-133`, `src/components/zest/ZestSimulator.tsx:703-705`
- **Issue:** `ZestHero.tsx` nests an `.apple-card` inside another `.apple-card` container (Gate 4 violation). Both `ZestHero.tsx` and `ZestSimulator.tsx` render colored traffic light circles simulating macOS window chrome without real window actions (Gate 47a / Gate 63).
- **Proposed Fix:** Flatten into a single containment layer and replace simulated window traffic lights with clean technical breadcrumbs or HUD status indicators.

### Group 2: Purpose-Gate / Medium (Priority: MEDIUM)

#### [Finding 13] R-04 / Gate 63 · Glued Arrows and Decorative Status Dots
- **Rule:** R-04 (Icons), R-08 (Button Arrows), Hallmark Gate 63
- **File:** `src/components/Projects.tsx:261`, `src/components/Hero.tsx:49,71`, `src/components/Footer.tsx:19`, `src/components/Languages.tsx:73,78`, `src/components/zest/ZestHero.tsx:20,41`
- **Issue:** `Projects.tsx` glues an arrow to link text (`Interactive Showcase →`). Multiple sections place green/teal status dots next to static copy ("open to remote", "v1.2", "Selected Work") without real operational status.
- **Proposed Fix:** Decouple arrows into separate SVG icons; remove non-operational status dots or pair them with semantic `<span role="status">` indicators.

#### [Finding 14] R-06 / Gate 75 · Micro-Typography Straining Under 12px
- **Rule:** R-06 (Typography), Hallmark Gate 75, UI-UX-Pro-Max Priority 6
- **File:** `src/components/Hero.tsx:198,206`, `src/components/zest/ZestHero.tsx:120`, `src/components/zest/ZestSimulator.tsx:406,416`
- **Issue:** Over 110 elements render typography at 9px, 10px, and 11px (e.g. `text-[9px]`, `text-[10px]`, `text-[11px]`). While acceptable for secondary badge numbers, functional labels and descriptions strain legibility on mobile screens under outdoor light.
- **Proposed Fix:** Establish a strict 12px minimum floor for functional text, reserving 10px-11px exclusively for mono tabular numerals and keyboard keycap glyphs.

#### [Finding 15] R-06 / Gate 64 & Gate 67 · Monospace & Tracked Caps as Decoration
- **Rule:** R-06 (Typography), Hallmark Gate 64 & Gate 67
- **File:** `src/components/Macropad3D.tsx:34-105`, `src/components/Hero.tsx:201`
- **Issue:** Keycap sublabels use all-caps monospace strings (`OVERVIEW`, `CAREER HISTORY`, `FEATURED APPS`) which Hallmark flags as "mono as costume" (Gate 64) and tracked caps (Gate 67).
- **Proposed Fix:** Use the brand sans body face in sentence or title case, untracked.

#### [Finding 16] R-10 / Hallmark Warn 29 · Stacked Glassmorphism on Mobile Viewports
- **Rule:** R-10 (Glassmorphism), Hallmark Warn 29
- **File:** `src/app/globals.css:153-165`
- **Issue:** Navbar, mobile accordion menu, and shelf controls all apply `backdrop-filter: blur(20px)` simultaneously. On lower-end mobile devices, multiple stacked backdrop blur layers trigger compositor repaint overhead.
- **Proposed Fix:** Restrict backdrop-filter to the sticky navbar, using solid tinted surfaces (`--bg-card`) for mobile popovers and card surfaces.

#### [Finding 17] R-14 / R-05 · Repetitive Bento Card Composition Rhythm
- **Rule:** R-14 (Feature Cards), R-05 (Layout & Rhythm)
- **File:** `src/components/Skills.tsx`, `src/components/Languages.tsx`, `src/components/Education.tsx`
- **Issue:** Three consecutive sections use the identical 2-column bento card grid with identical internal padding, borders, and icon placement, creating visual fatigue on desktop and a uniform vertical card stack on mobile.
- **Proposed Fix:** Introduce rhythmic variety: render Languages with horizontal pill bars, and Education with an Apple-style vertical timeline stem.

### Group 3: Quality Locks / Consistency (Priority: LOW)

#### [Finding 18] R-05 · Missing Section 01 Heading Lockup in Portfolio Root
- **Rule:** R-05 (Layout & Page Structure)
- **File:** `src/components/Hero.tsx`
- **Issue:** Experience starts at `02`, Projects at `03`, Skills at `04`, Languages at `05`, Education at `06`. The Hero serves as `#about` (matching Macropad key `01`), but lacks an explicit `01 About` section badge, causing an apparent numbering discontinuity.
- **Proposed Fix:** Add an explicit section indicator `01 About` above the portrait lockup or in the section anchor.

#### [Finding 19] R-29 / Gate 74 · Stock Tailwind Swatch Palette in Zest Components
- **Rule:** R-29 (Color Palette), Hallmark Gate 74
- **File:** `src/components/zest/ZestHero.tsx:146`, `src/components/zest/ZestSimulator.tsx:853+`
- **Issue:** Components use hardcoded Tailwind classes (`bg-emerald-500`, `bg-amber-500`, `text-amber-600`, `text-neutral-400`) instead of the project's semantic color tokens.
- **Proposed Fix:** Map these accent states to existing tokens (`var(--teal)`, `var(--shuiro)`, `var(--brass)`).

#### [Finding 20] UI-UX-Pro-Max Priority 5 · Table Horizontal Overflow on Mobile
- **Rule:** UI-UX-Pro-Max Priority 5 (Layout & Responsive)
- **File:** `src/components/zest/ZestComparison.tsx:110-135`, `src/components/zest/ZestShortcuts.tsx:95-130`
- **Issue:** Fixed 3-column tables exceed 390px mobile viewport width (396px–420px). While wrapped in `overflow-x-auto`, there is no horizontal swipe affordance or edge fade cue.
- **Proposed Fix:** Add a subtle right-edge fade mask or switch to a stacked card layout on `<640px` viewports.

#### [Finding 21] UI-UX-Pro-Max Priority 3 · Three.js ShadowMap Deprecation Warning
- **Rule:** UI-UX-Pro-Max Priority 3 (Performance)
- **File:** `src/components/Macropad3D.tsx`
- **Issue:** Emits runtime warning in Three.js v0.187+: `THREE.WebGLShadowMap: PCFSoftShadowMap has been removed. Using PCFShadowMap instead.`
- **Proposed Fix:** Update `renderer.shadowMap.type = THREE.PCFShadowMap`.

#### [Finding 22] Hallmark Gate 49 · Copy Email Button Layout Jitter
- **Rule:** Hallmark Gate 49 (Clickable Label Sizing)
- **File:** `src/components/Hero.tsx:114`
- **Issue:** Toggling between "Copy email" and "Copied to clipboard" changes text width without `min-w` containment, causing slight layout jump on screens <360px.
- **Proposed Fix:** Add fixed `min-w-[170px]` and `whitespace-nowrap` to the copy email button.
